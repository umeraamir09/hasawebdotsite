# Portfolio components

`@hasaweb/components` contains markup-only React components shared by client preview and static snapshot output. Schema contracts remain in `@hasaweb/schema`. The fixed profile precedes optional components in their saved order. Stable component IDs remain in `data-component-id` for editor selection.

`projectPortfolio(draft, options)` accepts an already validated `DraftDoc`. Its `resolveAsset({assetId, purpose})` callback returns an authorized ready absolute URL or `{state: "unavailable"}`. `assetOrigins` contains exact trusted origins. The caller must check owner, asset purpose, readiness and applicable access before resolving. Missing references remain missing; untrusted URLs become unavailable. IDs never become guessed storage paths.

The resulting `PortfolioModel` includes display fields only. Display strings normalize CRLF/CR to LF and replace NUL/unpaired surrogates with the replacement character. This makes browser DOM and HTML parsing agree while leaving the saved draft unchanged. The bridge parser and bounded static entry apply the same normalization. It omits recipient configuration, private graph consent, raw asset IDs, disabled second photos, setup/address/recovery data and untouched samples. It preserves the selected GitHub username while reporting its graph unavailable. Projects, skills, experience, text and shared link placements render their entered content. Since Phase 35 the model also carries the saved preset `appearance` (`themeId`, `fontId`, `colorMode`); an absent field means the approved defaults. The custom color is not projected. Since Phase 37 it carries the saved decoration, and since Phase 38 an enabled Face Reveal adds `profile.faceReveal.image`: the second photo resolved with the `face` purpose (ready, missing or unavailable). A disabled photo is never projected or resolved. Service contact/graphs activate in their later roadmap phases. Projection does not establish publication readiness.

`Portfolio`, `PortfolioProfile`, `PortfolioSection` and `RichText` render controlled markup without hooks or event handlers. Links use the schema's safe-destination rules. Owner text stays literal. Missing required fields and unavailable services have visible messages. Optional absent project images do not create image slots. Absent code/demo links omit the entire link row. Phase 28 adds manual editing through the shared editor controller; project cards retain saved order and use the same markup during publication. The source text heading levels remain relative to the component heading. Phase 32 work-experience descriptions are plain text; a scoped `white-space: pre-line` rule keeps the owner's line breaks identically in the preview and published pages, and an absent organization link renders no `<a>`.

## Browser adapter

`@hasaweb/components/browser` exports `mountPreview(element, model, {assetOrigins})`, returning `update(unknown): boolean` and `dispose()`. Invalid updates return false without replacing the displayed content. Dispose releases React, image and theme listeners.

`attachPreviewBridge({target, root, parentWindow, parentOrigin, channel, identity})` installs the child receiver and returns its cleanup function. `connectPreviewBridge({iframe, origin, channel, identity, onState, onSelect})` installs the parent connection and returns `request(prepare)`, `select(selection)` and `dispose()`. The parent accepts the child's authenticated owner/portfolio identity before sending any model. Both sides pin the source window, exact origin and per-mount channel. These checks supplement authentication; the bridge does not authorize HTTP or asset access.

The version-1 protocol uses ready/hello, begin, acknowledged chunks, finish, applied/rejected, unavailable, cancel and selection messages. It replaces the Phase 16 whole-model wire format. Transfers use at most 65,536 bytes per chunk and one outstanding acknowledgement. The receiver keeps one bounded assembly with a 15-second timeout. Supersession, navigation and disposal cancel old work. Each mount uses an increasing render sequence independent of saved draft CAS revisions. Only a successful mount update acknowledges display. Rejection preserves the last displayed model and exposes a separate refresh failure. An unavailable session clears the old display acknowledgement. A restored browser page resets the handshake and display sequence; the editor child reauthorizes its original owner before remounting.

`projectPortfolioCancellable(draft, options, signal)` shares the synchronous projection's adapters. It yields across collection rows. The transport normalizes and escapes strings in 4,096-code-unit pieces, with yields after 256 operations or 32,768 encoded bytes. Queued tasks permit cancellation without depending on nested timer delays. Final strict parsing and React rendering are atomic browser work, not a CPU feasibility claim.

The draft allowance remains 1 MiB. Ready URLs retain the schema's existing 2,048-byte HTTP(S) limit and exact trusted-origin check. The supported display envelope reserves eight source-byte allowances for field copies, scalar/key accounting, array indices and generated groups. It adds `floor(1 MiB / 94) + 3` possible images, each charged `2 * 2,048 + 128` bytes, plus 4,096 fixed bytes. An image-bearing project entry needs at least 94 source JSON bytes; only three profile images can be added (avatar, banner and the enabled Face Reveal photo; Phase 38 raised this from two). The double URL allowance covers JSON quote escaping. Display traversal allows at most `2 * 1 MiB + 128` values, depth 64 and 1,048,576 UTF-16 units per string. [Phase 17 tests](src/preview-transport.test.ts) cover exact-limit text, more than the old 250,000 values, cancellation and image-heavy models with maximum-length escaped URLs. New projection shapes must preserve or revise this derivation and its tests before expanding support.

The editor resolves private images through owner-authorized, purpose-checked asset reads before display projection. The child preview permits the exact application origin for these private image URLs. Shared crop controls retain only completed image files and replace draft references after readiness. See the [crop control results](../../specs/2026-10-22-upload-crop-controls/results.md), [private upload protocol](../../apps/web/lib/assets/README.md), and [editor results](../../specs/2026-10-20-editor-live-preview/results.md). The static fragment envelope and Phase 24 preparation/budget requirements are unchanged.

### Full-page preview pages

Phase 39 adds `projectPreviewPage(draft, path, options)` and `mountPreviewPage(element, page, {assetOrigins, pageBase, storage})` for the private full-page preview. The projection maps `/`, `/resume` and `/projects/{slug}` to the page a published portfolio would have, or returns `undefined` where the published site would show its page-unavailable state (no such case study, or no resume component). A page model is the strict `{model, page}` pair: the display model plus a `portfolio`, `case-study` (title, position, body and a per-asset image map) or `resume` (`DisplayFile`) page. Subpages carry the profile and appearance but no sections. The pair never crosses the iframe bridge, so the live-preview envelope above is unchanged. `PortfolioPage` composes the same `PortfolioProfile`, `PortfolioSection`, `PortfolioCaseStudy` and `PortfolioResume` views as publication. `mountPreviewPage` shares its lifecycle (strict parse with origin rechecks, appearance attributes, one React root and `installSite`) with `mountPreview`, then rewrites each `a.pf-page-link` under `pageBase` (`/preview`). Its visitor-mode toggle uses tab-scoped `sessionStorage`, tagged with the owner's saved mode, so a choice follows the owner across preview pages as origin storage follows a visitor across published pages and still resets when the saved mode changes. Nothing is stored beyond the tab. The preview projection resolves a resume with `viewUrl` set to the private inline variant.

## Platform files

`@hasaweb/components/styles.css` imports source-equivalent avatar CSS and the generated `themes.css`. That file declares all three approved self-hosted font faces and all six presets with their exact catalog light/dark tokens. The document element carries `data-theme`, `data-font` and `data-initial-mode` (the owner's saved light/dark/system mode), and the visitor's choice is `data-color-mode`. Dark applies for an explicit dark choice, for an owner dark mode without an explicit light choice, or for a dark system preference when neither chose light. Leaf also covers a document without `data-theme`. A browser downloads only the font family that `data-font` selects.

`@hasaweb/components/site-entry` bundles the standalone vanilla script. It is loaded render-blocking in `<head>`: its first statement, `applyStoredMode(document)`, copies a stored `hasaweb-color-mode` choice to `data-color-mode` before the body is parsed, and `installSite` attaches the native theme control and image slots at `DOMContentLoaded`. Public pages store the choice per origin, so it follows the visitor across that portfolio's pages. The theme button names its next action, `Dark mode` or `Light mode`, without a pressed state. Storage failure preserves the current-page toggle. No visitor cookies or tracking are added.

`mountPreview` applies the model's appearance attributes to the preview document. Its toggle uses an in-memory store: the choice survives content updates, resets when the saved mode changes and is never written to storage. `appearanceAttributes`, `appearanceModelSchema`, `displayAppearance` and `fontFileName` are exported from `@hasaweb/components` (`./appearance`). `displayAppearance` shows the defaults in preview for an unknown historical ID; publication validation rejects such IDs instead.

`static/manifest.json` maps the approved clean cat loop/still and the three original font files to content-hashed URLs. Keep each SIL OFL notice (`OFL.txt` for DM Sans, `OFL-manrope.txt`, `OFL-lora.txt`) with font distribution. Bundle CSS imports into a content-hashed stylesheet, bundle the public script separately, and retain their old bytes with each renderer version. Actual asset promotion and retention remain Phase 24.

`PortfolioAvatar({asset, decoration, faceReveal})` supports explicit `none`, `cat` and `hands` specimens with owner-data images. The portfolio projection carries the saved selection as `profile.decoration` (`none`, `cat` or `hands`; an absent or unknown `decorationId` is `none`), and `PortfolioProfile` renders it with the projected Face Reveal photo, so the editor preview and the publication dispatcher produce the same avatar slot.

Phase 38 activates the visitor behavior in this markup and in `installSite`, which both `site-entry` and `mountPreview` run:

- **Face Reveal.** With a photo the portrait is the source's native `<button data-face-reveal>` holding the avatar (`pf-avatar-illustration`) and photo (`pf-avatar-photo`) slots in one box, plus an `aria-hidden` swap cue. Markup starts on the avatar with `aria-label="Reveal face"`. Activation (click, Enter, Space) toggles `data-photo`, switches the label to `Show avatar`, and runs the source 620 ms diagonal wipe unless reduced motion applies. The source in-progress guard ignores a second activation during the wipe. A reduced-motion change mid-wipe ends it. Without Face Reveal the portrait stays a plain `<div>` with no cue or second image.
- **Playback.** A selected decoration adds `data-playback="playing"` to the frame and a `hidden` `<button data-avatar-playback>` (`Pause animation` / `Play animation`). The script shows it unless reduced motion applies. Pause sets `data-playback="paused"`: the cat's still `<source>` media becomes `all`, so the cleaned still shows, and the hands take the source reduced-motion still with no running animation. Play restores the full sequence from its start. Reduced motion shows the same stills, hides the control and takes priority; its changes apply at once. Pausing never changes the portrait, and the wipe still plays while paused.
- **State.** Each page load starts from the markup: the original avatar, playing. A back/forward-cache restore returns to the avatar. State is never stored. Script state lives in DOM attributes, so a preview content update that keeps the same elements keeps the visitor's state.

`static/avatar-reveal.css` holds these platform rules and the phone-width control layout; the generated `avatar.css` is unchanged. The generator template in `scripts/generate-renderer-avatar.mjs` emits the reveal button and playback control, so regenerate rather than edit `avatar.tsx`. The original source React component is unchanged. Run `pnpm generate:renderer-assets` to derive the shared SVG markup, namespaced CSS, `themes.css` and manifest from those sources and the catalog. This copies the source clean cat bytes and does not rerun or weaken its failed regeneration guard. The wrapper maps renderer palette variables into source avatar variables so dark mode uses the correct surfaces. The source portrait wrapper owns the border and corner clipping. Its nested image slot adds neither, preserving actual image bounds and offsets during loading, success and failure.

See the [renderer contract](../render/README.md) and [Phase 16 evidence](../../specs/2026-10-19-shared-portfolio-renderer/results.md).

## Inactive bounded publication preparation

`@hasaweb/components/frames` exports a closed set of existing portfolio wrappers for the [S-8 preparation protocol](../../specs/2026-10-24-s8-dispatch-feasibility/protocol.md). It cannot select arbitrary tags or inject HTML. The rich-text view accepts an optional trusted image resolver for case-study images; private/public authorization remains at the caller boundary. Asset units reuse `AssetImage` and the existing cat/hands avatar views. These helpers do not activate publication or change saved appearance selections in the editor. The [paid-at-launch policy](../../docs/deployment-policy.md) authorizes local reuse through the integrated S-8 milestone; the [evidence](../../specs/2026-10-24-s8-dispatch-feasibility/results.md) retains historical Free failures and pending release checks.

`PortfolioProject` is the shared project-card view used both by complete sections and bounded S-8 entry rendering. Since Phase 30 a project with a case study renders `Read case study: {title}` as a `pf-page-link` to its `caseStudyPath` (`/projects/{slug}`), replacing the earlier placeholder. `PortfolioCaseStudy` renders a case-study page body after the shared profile: a `page-nav` back link to `/` and the titled rich-text section. The `page-link` and `page-nav` frames accept only a same-site `path` (`/` or `/projects/{slug}`), separate from the external-link `href` allowlist. Bounded publication emits the same frames. Phase 34 adds `/resume` to that path set. The resume section renders `Download resume (PDF)` as a `pf-button` link to the resolved PDF and `View resume` as a `page-link` to `/resume`. `PortfolioResume` renders the `/resume` body after the shared profile: the back link, an `<object>` viewer of the same file's `viewUrl`, fallback text and the download control. The display model carries `{ state: "ready", url, viewUrl }`, `missing` or `unavailable`; origin checks cover both URLs. Phase 35 moved the platform script into `<head>` as a blocking script and added the appearance attributes (`publication-v4`). Phase 38 changed the avatar markup, platform CSS/script and the avatar image command, so `PUBLICATION_RENDERER_VERSION` is `publication-v5`. The bounded avatar command streams the Face Reveal description in its own slot: `open`, avatar description, `face`, photo description, `close`.

Skills project to groups in category order, followed by one unnamed trailing group of uncategorized skills; each group keeps saved entry order and empty groups are omitted. Category removal in the editor leaves its skills uncategorized. Skills never render ratings, levels or extracted content.
