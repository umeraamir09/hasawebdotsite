# Reserved address selection

Owners explicitly save an address to reserve it. Availability checks and typing reserve nothing. A held address creates no public site.

## Entry points and prerequisites

Run `pnpm verify --profile=drafts` for the owner draft API, autosave and editor fixtures. The editor recipe documents their ports and seeded handoff state. Schema or migration changes require the full profile, including persistence checks.

The reusable control is in the editor handoff fixture. Production `/editor` remains the account shell and the required Address guide screen is not activated by this phase.

## Drive the control

Fill the field labeled `Address name`. Verify typing remains local and leaves the authoritative reservation unchanged. Click `Save address`. Require a confirmed draft revision and matching held namespace row before treating the name as reserved. Reload and compare the field with the saved draft and registry.

Test a successful replacement and an unavailable replacement. The failed replacement must leave both the old hold and draft unchanged. Exercise the control at narrow widths and with the keyboard. A permanent claimed address must remain fixed.

## Check recovery and persistence

Read the draft API, autosave and editor reports from the printed verification directory. Confirm lost-reply retries return the exact durable command receipt. If another device has since changed the address, require reconciliation or conflict review before displaying the old name as current. A historical receipt proves an earlier commit, not the current hold.

The persistence suite covers real D1 rollback after zero-row revision CAS, racing holders, dynamic reserved names, foreign commands, generic and staged mirror guards, old migrations, account-deletion release and permanent orphan claims. Source assertions alone do not establish those results. Read the completed run report.

## Remaining boundaries

Setup handoff validation remains Phase 22A. First Publish converts the existing owned hold to a permanent claim in Phase 25. This recipe does not prove either later service, production CPU limits or a deployed public site.
