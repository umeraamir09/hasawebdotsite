## Decisions dependent work must preserve

| Change from earlier plans | Required handling | Dependent phases |
| --- | --- | --- |
| OpenNext hot APIs and full-body 1 MiB saves exceeded the CPU target. | Keep the web adapter and named Hono/jobs entry. Use bounded changes/staging and streamed draft reads. Do not add whole-document parsing/validation/serialization to this hot path. Retest changed handlers. | 14–15 and later owner APIs |
| Phase 13 is the current HTTP contract, extending the Phase 11A repository experiment. | Use `GET /api/owner/draft`, metadata-only progress reads and `POST /api/owner/draft/:action`. Preserve setup/content context, revision CAS, one attempt per owner, sequence/replay rules and explicit recovery. Send `X-Expected-Owner-Id`, compared only against authenticated identity, and verify the response portfolio ID. Conflicts return codes; fetch/reconcile separately. Never silently discard an attempt. Pending metadata cannot reconstruct unknown unfinished content. Verify identical-command receipts; unknown lost-begin IDs require explicit discard/rebuild, and uncertain commands cannot transfer sessions before verification. | 14–15, 17, 22A, 42A–42F |
| Conflict resolution selects local changes against a separately fetched current draft. | Quiesce the old controller, preserve original/local/current comparisons and raw input, recheck the canonical revision, checkpoint replacements before conditional source retirement, keep the active scope's recoverable checkpoint when reviewing another archived record, and save through a fresh serialized scope. Recovery sign-in uses fixed same-tab `/auth/recovery` and `/auth/recovery/error` destinations with an identifier-only tab continuation. Check uncached identity before loading its records; wrong accounts keep the original untouched. Continuing preserved edits quiesces the active controller before source lookup and keeps fields suspended throughout restoration, including fresh prepared replacements, releasing the pause before receipt verification/saving or on failure. Restore pinned discard journals before changed-base checks while retaining working values and the original comparison base for review. Failed review checkpointing keeps the active controller usable. Clean authentication continuations offer ordinary account entry. Setup recovery after handoff contributes selected content only. | 17, 22A, 42A–42F, 49, 53 |
| Legacy validity is separate from schema version. | Generation 2 is required for validated reads/incremental saves. Use bounded validation actions with matching journals or raw owner recovery for rejected content. Metadata alone cannot authorize committing unknown destination corrections. Keep raw correction text separate and bound to its issue path/base revision; discard staging without erasing it. Do not expose the offline full-document validator, truncate destinations or mark all migrated rows valid. Update incremental validation, generation policy and equivalence fixtures together when schemas change. | Any schema/migration change, 14–15 |
| CPU success has a measured D1 cost. | Use the [Phase 14 measured client model](../specs/2026-10-18-shared-autosave-recovery/quotas.md), [historical Phase 13 handler budgets](../specs/2026-10-17-revision-aware-drafts/quotas.md) and the [earlier capacity model](../specs/2026-10-16-free-owner-saves/quotas.md). Dense collections, staging, retries and cleanup consume additional quota. | 14, 24, 42, 51–52 |

## Verification boundary

The [review results](../specs/2026-10-18-foundation-review/results.md) record fresh local checks. Prior phase results retain their original test counts, provider measurements and cleanup receipts. Phase 13's 22 provider cases met the warm p95 target in LHE. The [Phase 14 investigation](../specs/2026-10-18-shared-autosave-recovery/performance.md) records an initial failing KHI run and the current bounded-read/access-precheck follow-up. A passing location or warm sample does not establish global/cold CPU feasibility or publication capacity. Production callback/TLS checks, final dispatcher measurements, complete browser/accessibility coverage and the real signup-to-publication journey remain release requirements.

Preserve earlier receipts when rerunning harnesses. Set `DRAFT_API_EVIDENCE` for the draft API, `BOUNDED_SAVE_EVIDENCE` for bounded saves, and `--evidence-dir=...` for auth to the new phase's directory or an ignored `.wrangler/` directory. Their defaults write historical spec locations. Keep Wrangler suites sequential because inspector ports overlap.
