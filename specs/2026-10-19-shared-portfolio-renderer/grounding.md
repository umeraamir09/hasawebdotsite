# Renderer grounding

`packages/components` re-exports schema metadata and `packages/render` has no production exports at phase start. The canonical schema defines fixed profile, ordered typed components and stable entry IDs. PublicContent excludes setup candidate/sample metadata but still contains contact recipient IDs, so it is not a ready public transport payload. Asset references are IDs, never storage keys or provider URLs.

Incomplete strings and missing assets are valid drafts. Rendering is distinct from publication validation. Use existing `isWebUrl` and `isSafeLink` output checks and literal escaped React text. Rich text contains only schema-allowed headings, paragraphs, lists and link marks. GitHub, contact, resume and case-study services do not exist yet and must report honest unavailable states.

Markup-only React is shared between browser and static output. Published output runs no React. Production publication cannot render an entire maximum document in one invocation. S-1 requires bounded preparation/rendering and Unicode-safe splitting; S-8 rejects per-fragment Workflows and naive Queue messages. Phase 24 must measure batching, transfer, CPU and shared quotas with the real renderer. No renderer test is permission to activate publication.
