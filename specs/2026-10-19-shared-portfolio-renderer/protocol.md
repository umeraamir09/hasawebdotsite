# Phase 16 renderer protocol

Recorded October 19, 2026. The [selected design](design.md) supersedes both retained exploration candidates. This increment adds reusable renderer code and isolated evidence. It does not activate editor, public serving, publication or mandatory signup routes.

## Data and ownership

The canonical draft remains unchanged. An authorized caller projects its validated revision into `PortfolioModel` through `projectPortfolio`. Resolve asset purpose, ownership and readiness before supplying an exact trusted URL. The projection never constructs paths from IDs. Only display fields cross the preview bridge or static renderer. The contact recipient ID, private contribution consent, setup/candidate/recovery data, disabled second image and raw asset IDs are omitted. Untouched sample targets are omitted. Publication validation remains Phase 23.

Display text normalizes CRLF/CR to LF and replaces NUL/unpaired surrogates before either host renders it. The source draft stays unchanged. This prevents client DOM text and HTML-parser text from diverging. The bridge and fragment boundary apply the same rule.

The fixed profile precedes the saved optional component order. Component IDs survive projection and appear in markup for future selection. Link placement uses the shared source entries. Missing required content remains readable with honest messages. Optional absent project images/links remain absent. GitHub retains its selected username and profile link while its graph is unavailable. Contact, resume and case-study navigation report unavailable until their services exist. No fake graph, sent-message success, downloadable file or page route is emitted.

Default Leaf tokens derive from the approved catalog. DM Sans uses the catalog's original TTF and SIL OFL notice. Both hosts share CSS and the same vanilla theme/image behavior. Browser preview mounts React on the client; snapshots contain markup plus a standalone script. The unchanged imported React avatar remains a reference. A generator derives separate owner-data SVG/CSS and copies the exact cleaned cat bytes. Explicit cat/hands specimens preserve responsive geometry and reduced motion, while saved decoration/Face Reveal/playback activation remains later work.

## Preview boundary

Mount only after an authenticated owner check. Authorize every draft asset independently. Pin the permitted frame parent in response CSP and retain noindex/private/no-store. The host sends `{channel, revision, model}`, where revision is a per-mount render sequence rather than the saved draft CAS revision; the bridge requires the configured window, exact origin, matching channel, increasing safe integer and strict bounded display model. Invalid messages do not replace the displayed draft. Dispose the bridge/mount on teardown or owner changes.

The current browser envelope is a 2 MiB accounting budget, 250,000 traversed values, depth 64 and 1,048,576 units per string. It is separate from the owner's 1 MiB draft allowance. Resolved URLs can expand the model, so Phase 17 must provide bounded chunking/cancellation before supporting any valid model beyond this envelope. A rejected update cannot be reported as displayed. These checks are browser-side, not whole-document hot Worker parsing.

## Snapshot boundary

The production entry serializes one prepared profile/component within the [documented fragment guards](../../packages/render/README.md#fragment-boundary). It validates data and asset origins before React serialization and checks output bytes afterward. Oversized input returns `needs_partitioning`, without truncated output. The offline entry can render a complete resident model for fixtures only.

Phase 24 must prepare and split large Unicode strings, nested rich text, descriptions and large collections without repeating wrappers or changing list semantics. Preparation must be revision-bound and resumable or transactionally normalized, rather than parsing/partitioning a whole maximum draft in a hot invocation. Measure the actual final fragments, generated art, CPU, batching, request counts, D1/R2/Queue costs and assembly. The bounded API is not a complete publication pipeline and cannot handle every valid component in one fragment. S-1 and S-8 remain controlling; no new content limit or paid-plan assumption is introduced.

Platform CSS/JS paths contain content hashes. Font/art URLs contain hashes of their original bytes. A configured exact asset origin supports the dedicated asset host. Phase 24 promotes and retains these files and Phase 25 applies response policy while streaming snapshots. Current cache headers preserve the existing must-revalidate boundary; actual edge/query/browser withdrawal remains unverified under S-9.

## Evidence method

The repeatable browser script compiles one synthetic draft fixture into separate private and published display models. Only asset URL namespaces differ, and both resolve to identical bytes. The private host sends its model into a client-mounted iframe. The public path serves HTML generated by the separate offline helper. Both load the same content-hashed CSS/vanilla script and approved font/art.

Compare content, section IDs/order, safe links, image descriptions/sizes, section geometry, font family, colors and overflow for complete, incomplete, empty and long Unicode fixtures at 360, 768 and 1280 pixels. Also exercise a 390-pixel iframe, rejected bridge messages, valid replacement, native Enter/Space/focus/skip behavior, stored/system modes, CSP script rejection, delayed/error images, cat/hands geometry and changing reduced motion. Measure actual avatar image bounds and offsets within the source portrait wrapper, including loading and failed images. Outer-wrapper dimensions alone cannot prove source geometry. Check the theme button's action name and absence of pressed state before and after Enter and Space in both hosts. Retain screenshots and machine-readable checks. Axe checks the complete static fixture against WCAG AA tags and does not replace these explicit control checks.

Private fixture sessions deny signed-out and other-owner requests to the host, model and assets. This proves isolated harness gating only. It does not prove real Better Auth preview/upload route integration, which remains Phases 17, 18, 39 and 42E. Chromium evidence does not establish the full release browser matrix. Phase 53 retains that requirement. No production deployment, CPU benchmark or owner phase checkoff occurs here.
