## Decisions

- **Explicit Add graph; the component follows the server.** The screen first shows only an explanation and Add graph. The panel appears after that choice, and `acceptGraph` creates the graph component only when the setup route accepts a username. That includes a selection whose first fetch failed, so Retry needs no retyping. Visiting, skipping, a GitHub signup and a GitHub profile link therefore add nothing, and no untouched graph component can exist to clean up.
- **Detection stays a suggestion.** A GitHub signup sees the existing "We detected @login … Use @login" control; a Google owner types any public username. Neither path links a sign-in provider.
- **Continue needs a complete configuration.** Continue reads `GET /api/owner/github` and requires: the account the draft names is the server's selection, the public fetch succeeded (zero contributions included; a failed refresh with last good data still counts), and, when the draft includes private activity, a `ready` authorized calendar (`graphGap`). Without a graph, Continue proceeds unless Add graph was chosen with nothing accepted. A gap shows the reason and a "GitHub needs attention" note (Figma `330:492`) with **Finish later in the editor**, which saves progress and keeps the unfinished graph. Its existing publication blocker applies. The panel already offers Retry, Authorize again and Use public activity only.
- **A `setup` consent return context.** `POST /api/owner/github/consent` now accepts `{"returnTo":"setup"}` beside `editor`. The context is stored with the attempt (migration `0017_github_consent_setup_return.sql` rebuilds `github_consent` to widen its CHECK; D1's `defer_foreign_keys` replaces drizzle's `foreign_keys=OFF`, and no table references `github_consent`). The callback maps it to the fixed `/auth/entry?github=consent`: the account entry that Phase 42E resolves to the guide and its saved step. A replayed, expired or other-session callback of the same owner returns to the stored context. A signed-out visit and an unknown state still go to `/editor?github=consent`, which sends the owner to sign-in. After sign-in, account entry resumes the guide from saved progress, so the URL does not need to know the context.
- **Return to the saved step.** Before leaving for GitHub, the screen saves progress `github` and flushes the draft (the private choice included). The guide shows the step from saved progress, not from the URL, and removes the `github=consent` marker. The outcome comes from the status route, as in the editor.
- **Skip and removal.** Skip this step and Skip remaining steps follow 42C (target Review) and never disconnect: the component, connection and grant stay. Remove graph opens the shared removal dialog with the withdrawal explanation, calls `withdrawGraphAccess` first and removes the component only after it succeeds.
- **Copy and layout.** Read-only inspection of Figma `326:503` (desktop GitHub step) and `330:492` supplied the title "Your activity, at a glance", the intro, the outlined field/buttons and the surfaced private block. The editor stylesheet isn't in the guide bundle, so the panel is styled under `.guide-github`. The Figma frame shows the username field before any choice; the guide keeps an explicit Add graph first, as the phase scope requires. Nothing in the file was changed.

Reconnecting then works, and a further cleanup sweep revokes nothing.
