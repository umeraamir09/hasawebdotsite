## Decisions

The data shapes are an authenticated owner/portfolio session, coordinator-owned current controller, stable field paths/component IDs and a display-only preview model. One controller remains the save owner. Fields use raw input before valid working values and clear only accepted legacy sample markers. Controller `scopeKey` replaces field/selection state. Ordinary preserved input uses `continueRecord`; prepared replacements use `reopen`. Both quiesce before source-storage lookup. Coordinator disposal now closes current and temporary writers and prevents new writers or commands after editor exit while preserving local checkpoints. Auth recovery uses the same disposal boundary and existing fixed callbacks.

The design comparison chose an authenticated child document over parent-owned direct rendering. It reuses the established renderer/bridge and keeps one strict display parser. Requested and last-displayed sequences and cancellable byte/node preparation came from the alternative. Origin, source, channel and authenticated identity are pinned. Acknowledged 64 KiB chunks carry only display fields. Rejected updates retain honest status; unavailable sessions remove the old display. Iframe replacement and persisted browser return reset the handshake and sequence. The child rechecks the original identity before remounting. Final parsing/rendering remains atomic browser work.

The draft stays at 1 MiB and URLs keep the existing 2,048-byte schema limit. The [component contract](../../packages/components/README.md#browser-adapter) derives the expanded byte/node envelope from source size and the minimum image-bearing entry. [Boundary tests](../../packages/components/src/preview-transport.test.ts) cover minimum entry shape, maximum escaped URLs, image-heavy exact-limit drafts and dense models exceeding the old node envelope. New projection shapes must update that derivation and its tests. Real images remain unavailable until Phase 18 supplies owned, ready, purpose-matched asset access.

Throughput checkpoint. Approval/contract checks preceded implementation. Read-only draft/renderer exploration and isolated design candidates ran independently. One implementation owner controlled the coupled editor/bridge files. The lead took over after the account usage interruption and the owner's instruction to continue. Heavy checks use `pnpm verify` and its shared resource lock. Phase 18 is outside this work.
