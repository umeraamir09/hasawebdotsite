## Decisions

The immutable asset ID, pending/ready/failed state, purpose, media type and actual bytes are the upload data shape. The web Worker handles binary requests before OpenNext and retains exclusive draft R2 ownership. A bounded declared-size header supports browser File framing, while independent byte counting and a FixedLengthStream enforce the actual body size. Finalization uncertainty is reconciled before cleanup. Future setup/publication callers receive an owned-ready-purpose resolver without activating dormant owner UI.

The HTTP runtime disposes unread rejected bodies. Eager application cancellation reset the connection during exact-limit rejection tests. Consumed transfers still cancel on errors and deadlines; an already-aborted input is canceled before storage begins. The [selected reproduction](oversize-response-reproduction.md) preserves the failing and corrected behavior.

Throughput checkpoint. Prove browser framing and real R2 streaming first, then complete authorization and failure cases, then run targeted verification under the shared lock. The coordinator owns the integrated full gate and separate security review.
