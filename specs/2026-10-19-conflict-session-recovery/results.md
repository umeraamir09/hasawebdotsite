## Implemented behavior

The shared recovery coordinator quiesces its source controller, records the in-flight acknowledgement and checkpoints latest local values. Every subsequent controller command, including legacy validation, stops while suspended. Review reads canonical content separately and compares original/local/current values. Stable IDs identify collection entries; additions, removals, reorder, rich text and coupled objects remain explicit selections. Structural application preserves unrelated newer fields inside the selected objects and keeps remotely missing entries for review without automatic recreation. Raw field input and legacy correction text remain separate, with original issue paths/base revisions.

Load newer version asks for replacement confirmation and retains a review-only local copy. Keep my edits for review starts unselected. Checkbox decisions are durable. Application rechecks revision/milestone and refreshes the comparison with cleared selections if either changed. It checkpoints a fresh replacement and prepared/resolved decisions before source retirement, then saves through the existing serialized bounded patch/staging machinery. Compare-and-delete protects source records another tab updated. Retained review copies do not block resolved work; clean replacement checkpoints do not block reload. Prepared replacements reopen in fresh record scopes and recheck revision/milestone before resuming unexecuted selections. A newer canonical revision retains the prepared target for review and resets selection. Saved still requires canonical acknowledgement, and active unfinished input reports Unsaved input.

Normal sign-in keeps `/editor`. Draft recovery uses fixed same-tab `/auth/recovery` and `/auth/recovery/error` destinations, with no arbitrary return URL. The strict version-1 tab continuation contains identifiers/context/controlled flow only. The callback checks uncached owner identity before opening any recovery range. Wrong accounts cannot read, copy or delete original recovery. Explicit continuation verifies interrupted-save receipts before writes. Cancellation, provider failure, Back and reload preserve recovery. Expiry during review preserves selected decisions. Matching continuations move to durable replacement IDs/context before source retirement or reviewed application, including fresh content scopes after setup handoff.

Existing unknown-staging, unverifiable-begin, validation-journal, uncertain-transfer, expected-sequence and lost-discard protections remain in force. Already committed terminal receipts may be retired only after a canonical read and durable local review preservation, through a linked fresh controller cleanup journal. Lost cleanup replies and reload continue that same pinned intent. This does not transfer/replay an uncertain command or acknowledge its local target. A discard that observed no attempt rejects a newly appeared one. Changed-base staging discard now checkpoints its durable block and original comparison base before clearing the journal. Applicable setup content may enter a fresh content scope only after explicit review; setup progress, prepared setup attempts and the permanent milestone are never replayed or reset. No provisioning, upload or publication behavior changes.

The controls reuse the existing warm surfaces, DM Sans and button language. Connected Figma MCP design context and screenshot for `12:48` were read without writes. The fixtures remain separate builds; no product route imports either browser helper. `/editor` remains the welcome shell. The callback supplies recovery only, with full editor/guide adapters in their owning phases.

## Post-review fix

- The Codex review on `44fde5dcac` found that `start(recordId)` retired the active scope's own recoverable checkpoint when it started a review of a different archived record (`recovery-coordinator.ts:222-223`). The active tab's newest working values and raw inputs were in neither the review copy nor storage, so a reload or the reviewed application could not recover them.
- Three regression tests were added first and failed on `44fde5dcac`: the active working values survive another record's review, unfinished raw input survives it, and the kept checkpoint stays listed after that review is applied.
- The fix exports the controller's existing `recoverable()` predicate and only retires the active checkpoint when it is clean. A clean record was already removed by `persist()`, so the conflict-panel path is unchanged. No UI change was needed: `adoptReviewed` and initialization already list preserved records.
- Isolated reruns passed the recovery coordinator suite (25 tests) and the draft client suite (94 tests); `pnpm check` passes with 318 unit tests. The browser, auth and persistence suites were not rerun for this fix, and no recorded receipt was rewritten.

## Second review fix

- The [second Codex review](https://github.com/umeraamir09/hasawebdotsite/pull/21#discussion_r4311810703) on `77a51d1` found that Continue preserved edits left field editing enabled during restoration. An edit accepted after `restore()` checked for dirty values but before its awaited storage lookup returned could be persisted, then overwritten by the restored working draft and checkpoint.
- `continueRecord` now quiesces the active controller before source lookup and keeps fields suspended through restoration. It releases the pause before receipt verification/saving. The existing action finalizer releases it after restore-only paths or errors. No controller mutation, receipt or save protocol changes were needed.
- Two regression cases held the storage lookup inside `restore()`. Both failed on `77a51d1`. They now verify suspension, rejection of edits during that wait, and resumed editing after successful restoration or a storage error. Successful continuation still saves the preserved values; failed lookup retains the source record.
- The draft client suite passes all 96 tests. `pnpm check` passes lint, all twelve typecheck tasks and 320 tests across 27 files. Browser, auth, persistence and production build suites were not rerun for this fix. Earlier evidence and counts above remain historical.
