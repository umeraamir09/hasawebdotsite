# Phase 26 publication and republishing

## Scope and acceptance

[Phase 26](../../docs/roadmap.md#phase-26-finish-publication-and-republishing-primitives) and [publication acceptance](../../docs/acceptance-criteria.md#15-subdomain-selection-and-publication) require saved-draft publication, honest progress and retry, address replacement before first publication, and safe withdrawal on republish. A profile-only handoff fixture must publish, reopen the saved editor draft and republish at the same URL.

Phases 14, 15 and 23 through 25 are owner-approved and integrated in `main` at `bb59130`. The [paid-at-launch policy](../../docs/deployment-policy.md#development-start-and-release-gates) authorizes implementation and local testing of S-9 policy in dependent phases; observed deployed withdrawal remains a release gate. Phase 08's live evidence did not verify browser TTL or warmed query variants. The Phase 25 serving boundary uses no-store headers and ignores query variants locally; these do not prove the deployed policy.

Worktree: `.wrangler/worktrees/phase26`, branch `feat/26-publication-finish`. Write boundaries: publication operation, editor fixture and address controls, withdrawal/cache handling, focused tests and affected guidance. No parallel implementation was requested.

## Decisions

Retained upload URLs are authorized only while the active version contains the same logical path and SHA-256 hash. This preserves old URLs for unchanged assets while denying removed assets at the origin after the pointer changes. An old page can consequently lose a removed image after a concurrent publication. This privacy boundary does not itself delete the object or purge caches.
